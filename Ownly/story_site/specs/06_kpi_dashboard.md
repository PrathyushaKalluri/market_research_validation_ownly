## Visual architecture (standard set by `final_dashboard/index.html` — keep it)
- **Left:** input drivers grouped by family (price, assortment, service, distribution, lock-in).
- **Middle:** the causal arrows into ACQUISITION and RETENTION.
- **Right:** outputs — funnel and retention signal.
- Each node: value (serif, large) · name · `n =` + evidence type · 95% CI.
- The two not-computable nodes are **ghost nodes**: outlined, unfilled, carrying the sentence that says
  what data would fill them.

## Per-KPI chart (the second layer, revealed as you scroll through the tree)
Each KPI expands into: **instrument → raw data → formula → value → interval.** One consistent grammar,
eight repetitions. Chart forms are specified per-KPI in the agent's document; the rule is that the form
must match the job (e.g. K13 is a staircase, not a bar; K7 is a dumbbell of two medians; K1a is a
win/loss dot strip over four baskets).

## Movement — what is legitimate
Allowed: the three price views (axis reads *what the customer has*, never "time"), the switching
staircase, the fake-door funnel, the research funnel drawn as nested bases, the randomised price ladder.
**Not allowed:** any date axis; **Bengaluru → Gachibowli as a trajectory** (two simultaneous samples, so
a paired dot plot with both intervals — they nearly touch at n=16); the Bengaluru orders/day ramp as a
curve (three press citations → three dated dots, no line); a zero bar for K17; any projection in the
north-star frame.

## The n<30 rule, enforced in the chart itself
K1a (n=4) and K4 (n=10) **may never be drawn as percentage bars** — our own sample rule forbids it.
K1a renders as `4 of 4` over a slopegraph of the three price views; K4 as `9 of 10` over a unit grid.
A value **counts up only if n ≥ 30**; below that it snaps in as a fraction.

## Motion
- Tree branches draw from the north star outward, 600ms with 80ms stagger.
- Values count up from 0 in 800ms, easing out; CIs fade in after the value settles.
- Ghost nodes pulse once, slowly, when they enter.

## Tech notes
- Charts generated by Python to SVG (pattern already proven in `FINAL_STORY/scripts/charts.py`), then
  animated in-page by adding classes — the SVG must ship with stable `id`s per element.
- Tree layout is hand-authored SVG with a JSON of node positions, not a graph library.
